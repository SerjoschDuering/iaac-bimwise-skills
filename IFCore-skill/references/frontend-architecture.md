# Frontend Architecture

React 19 + TypeScript app. Each feature (upload, checks, 3D viewer, categories, dashboard, report, chat)
is a **feature module** — a colocated folder with components + hooks. Backend operations are **async jobs**.

> **New to web development?** A frontend is the part users see and click on.
> The backend does the heavy work (running checks). They talk through an **API**.

## Root Layout (`__root.tsx`)

The root route detects workspace vs. non-workspace paths:
- **Auth views** (`/login`, `/profile`): minimal layout, no workspace chrome
- **Project list** (`/projects`): Navbar + content
- **Workspace** (`/projects/:id`, `/checks`, `/report`): 3-column grid layout:
  - **Left**: CategorySidebar (236px) — category cards + upload
  - **Center**: ViewerPanel + floating TechnicalDashboard dock (conditional rendering)
  - **Right**: ChatPanel (collapsible) — AI compliance assistant

The TechnicalDashboard dock uses **conditional rendering** (not CSS hiding) to avoid
running Recharts, KpiGauge animations, and DOM off-screen.

## Routing (TanStack Router)

File-based routing — each file in `src/routes/` becomes a route automatically.
The `@tanstack/router-plugin` Vite plugin generates `routeTree.gen.ts`.

Adding a route: create `src/routes/yourpage.tsx` with:
```tsx
import { createFileRoute } from "@tanstack/react-router";
export const Route = createFileRoute("/yourpage")({ component: () => <div>Content</div> });
```

## Async Job Pattern

Backend tasks (IFC checks) take 10-60 seconds. Everything uses **async jobs** with polling.

```
Frontend           Worker (proxy)      HF Space (FastAPI)
────────           ──────────────      ──────────────────
POST /checks/run → proxy           →   start background task
             ←── {jobId}           ←   return {jobId} immediately

poll GET /jobs/id  lazy-poll HF         ...working...
             ←── {status:"running"}

poll GET /jobs/id  lazy-poll HF    →   GET /jobs/{hf_job_id}
             ←── {status:"done", check_results, element_results}
                   ↓ remap job_id, insert to D1
```

**Why polling?** HF Spaces cannot resolve `*.workers.dev` DNS — callbacks don't work.
The CF Worker lazy-polls HF only when the frontend asks.

## Shared State (Zustand)

Five slices, combined in `store.ts`:

| Slice | Key state | Used by |
|-------|-----------|---------|
| `projectsSlice` | `projects[]`, `activeProjectId` | Upload, project pages |
| `checksSlice` | `checkResults[]`, `elementResults[]` | Dashboard, report, viewer |
| `jobsSlice` | `jobs{}`, `trackJob()`, `updateJob()` | Poller, check runner |
| `viewerSlice` | `ifcUrl`, `colorMap`, `highlightColorMap`, `selectedIds`, `hiddenIds`, `isReady` | BIMViewer, useViewer, useCategoryColors |
| `filterSlice` | `selectedCategory`, `selectedCheckId` | CategoryCards, TechnicalDashboard, useCategoryColors |

**Dual color map system:**
- `colorMap` — base check status colors (set by `useViewer` from elementResults)
- `highlightColorMap` — category filter overlay (set by `useCategoryColors` when a category is selected)
- BIMViewer merges both: `{ ...colorMap, ...highlightColorMap }` — highlight takes priority

**Performance patterns (critical):**
- `useViewer` and `useCategoryColors` use `getState()` with equality checks before writing to avoid re-render cascades
- `poller.ts` batches all state updates into a single `setState()` call when a job completes
- ChatPanel reads store at call time via `getState()` (doesn't subscribe to checkResults/elementResults)
- TechnicalDashboard uses conditional rendering (unmounted when dock is collapsed)
- Heavy computations wrapped in `useMemo` (stats, filtering, element maps)

## Constants (`lib/constants.ts`)

Shared source of truth for team categories and status colors:
```ts
CATEGORIES: { id, label, color, icon, team }[]  // 5 categories, mapped to team repo names
getCategory(team: string): Category | undefined  // lookup by team repo name
statusToHex(status: string): string              // check_status → hex color
STATUS_COLORS: { pass, fail, warning, running, ... }
```

## Feature Module Pattern

```tsx
// features/upload/UploadForm.tsx
export function UploadForm() {
  const { upload, isUploading } = useUpload();
  // ... render form
}
```

**Rules:**
- Don't import from other feature modules
- Read/write state through `useStore`
- Call backend through `lib/api.ts`
- One folder, one concern

## 3D Viewer (ThatOpen Components)

IFC rendered directly in browser via `@thatopen/components` v3 + `web-ifc` WASM.
No backend GLB conversion. See [3D Viewer Reference](./3d-viewer.md) for full details.

Key viewer modules:
- `BIMViewer.tsx` — engine init, IFC loading, color application, raycasting
- `useViewer.ts` — elementResults → colorMap (5 statuses: fail, warning, pass, blocked, log)
- `useCategoryColors.ts` — category selection → highlightColorMap
- `viewerActions.ts` — highlight/hide/isolate GUID helpers
- `viewerDiagnostics.ts` — phase tracking + error classification
- `ElementTooltip.tsx` — shows check results when an element is clicked

## Database (D1)

Eight tables across 3 migrations. See `migrations/` for full DDL.

**Core tables** (`0001_init.sql`):
```
users (id, email, name, team, created_at, email_verified, image, updated_at)
projects (id, user_id, name, file_url, ifc_schema, region, building_type, metadata, created_at)
jobs (id, project_id, status, glb_url, hf_job_id, started_at, completed_at)
check_results (id, job_id, project_id, check_name, team, status, summary, has_elements, created_at)
element_results (id, check_result_id, element_id, ..., check_status, actual_value, required_value, comment, log)
```

**Auth tables** (`0003_auth.sql`): `session`, `account`, `verification` — managed by Better Auth.

See [Validation Schema](./validation-schema.md) for details.

## Adding a Feature (Checklist)

1. Create `src/features/<name>/` with component(s) + hook(s)
2. Create `src/routes/<route>.tsx` with `createFileRoute`
3. If it needs new state → add a slice to `stores/slices/`, register in `store.ts` + `types.ts`
4. If it needs a new API call → add to `lib/api.ts`
5. If it needs a new backend endpoint → add Worker route + HF endpoint (see async recipe above)
